# Physics-held grabbables and missing furniture colliders (v1)

Held objects (pan, knife, plates, pot, bread, phone, ingredients) used to go kinematic and teleport to the hand, so they passed through walls, counters and the stove. A new runtime component, `HeldObjectPhysics`, is auto-installed on every dynamic `XRGrabInteractable` at scene load and switches the object to XRI `VelocityTracking` while held, so static colliders stop it. The scene also gets 14 BoxColliders on the chairs and bed, a Wall_Back resize that closes a 10 cm gap above the floor, and a 6 cm shift of Chair_B out of the Table. `Pan.cs`, `PanSnap.cs` and `KnifeSlicer.cs` are untouched, and I found no code path in them that assumes a kinematic held body.

Watch for: (1) the new chair seat colliders top out at 0.475 m while the rig's CharacterController has `stepOffset` 0.5, so the player can walk up onto a chair seat (likely). (2) Held objects now trail the hand by one 50 Hz physics step plus interpolation, with no predicted-visuals transform configured (likely). (3) None of the new PlayMode tests have run, and none checks the headline behavior, a held object being stopped by a wall (confirmed). (4) The pan-to-burner snap has no test for the new "hold, lower onto the stove, release" path (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The root cause of "pan goes through walls" was XRI's Instantaneous movement type, which makes the Rigidbody kinematic and sets its pose every frame. The fix leaves the grab setup in the scene untouched and flips the interactable to VelocityTracking when it is selected, restoring the original type on release. Throw-on-detach keeps working because XRI computes the throw itself, and the Rigidbody stays dynamic so walls, counters and the stove can block it.

While held, the object ignores the player rig's colliders so a pan held against the body does not fight the CharacterController. After release the ignore stays on until the colliders stop overlapping, so a dropped pan is not shoved by the capsule.

The component is added by a one-shot `RuntimeInitializeOnLoadMethod`, so no scene or prefab is edited. Objects present at first scene load are covered, and sliced halves inherit the component by cloning.

Pan, PanSnap and the knife do not depend on the held body being kinematic, and after release the body state matches the pre-change state, so snap timing should be unchanged. Nothing tests that.

The scene edits fix real gaps (chair and bed parts without colliders, Wall_Back 10 cm above the floor, Chair_B 5 cm inside the Table). The new chair colliders interact with the rig's 0.5 m step offset.

## VelocityTracking swap on select and the hand-lag trade-off

The swap happens in the `selectEntered` listener, after XRI has already run its Instantaneous grab setup. In the package source (`XRGrabInteractable.cs`, `UpdateCurrentMovementType`, lines 2155-2208), changing `movementType` while selected drops and redoes the Rigidbody setup, so the body ends up dynamic with gravity off and the original kinematic and gravity values are restored on release.

The cost is in-headset feel. The project's Fixed Timestep is 0.02 (50 Hz) while a headset renders at 72-90 Hz. VelocityTracking is applied in the physics step and the component forces `Interpolate`, which renders a body one step behind its latest physics pose. A held pan or knife therefore trails the controller by roughly 20-40 ms. XRI offers `predictedVisualsTransform` for this and the component does not use it. Confidence: likely.

The held body also gets velocities that reach the hand within one step (damping and scale are both 1). Pushing a held pan or knife into loose dynamic objects such as plates, bread, a sliced half or the pot applies large impulses and can launch them. A kinematic body pushed dynamic bodies before too, so this is a change in degree. Confidence: likely.

## One-shot installer at scene load

`InstallAll` runs from `RuntimeInitializeOnLoadMethod(AfterSceneLoad)`, which Unity fires once at startup. Grabbables that appear later (an additively loaded scene, a prefab instantiated at runtime that is not a clone of an installed object) get no component and keep the old pass-through behavior. The scripts under `Assets/Scripts` do not call `Instantiate`, and `KnifeSlicer` halves are clones, so the current game is unaffected. There is no per-object opt-out because the component is never serialized into the scene. Confidence: likely.

## Chair colliders against the rig's step offset

The new Chair_A_Seat and Chair_B_Seat colliders have their top face at 0.475 m (center 0.45, thickness 0.05). The XR Origin prefab's CharacterController has `m_StepOffset: 0.5` (radius 0.1, height 1.36). A CharacterController steps up onto any obstacle whose top is within the step offset, so a player walking into a chair should be lifted onto the seat, a sudden 47 cm camera lift in VR. Bed_Base (top 0.3) already had a collider before this change, so the bed was already climbable. Raising the seat colliders above 0.5 m, for example size y 1.8 and center y 0.4 in local units (top at 0.515 m, same bottom), avoids this without touching the rig. Confidence: likely, not confirmed in the Editor.

## Resolution

Compile check: `TOTAL ERRORS: 0` (runtime, PlayMode tests, EditMode tests). No PlayMode run was possible because the Editor is open, so the new tests are written but unexecuted. Scene file stays LF, no BOM.

1. **Chair seats climbable: fixed.** BoxColliders 920000003 (Chair_A_Seat) and 920000009 (Chair_B_Seat) in `SampleScene.unity` now use size `{1, 1.8, 1}` and center `{0, 0.4, 0}`. With the seat scaled to y 0.05 at height 0.45, the collider spans 0.425 to 0.515 m, above the rig's 0.5 m step offset. The collider sticks out 4 cm above the visible seat, so objects set on a seat rest 4 cm high. I accepted that over changing the rig.
2. **Held-object lag: not fixed, justified.** XRI only auto-assigns `predictedVisualsTransform` in the editor `Reset`, and it needs one dedicated visuals child. It moves that child's pose while the object is held. `KnifeSlicer` slices the child mesh and clones halves, and a clone made during a hold would keep a shifted child (XRI restores the pose only on drop). That could regress slicing, and the lag cannot be judged without a headset. Interpolate stays on, which trades up to one 20 ms step of latency for no jitter. If it feels laggy in the headset, assign `predictedVisualsTransform` per prefab for objects that are not sliced (pan, plates, pot, knife).
3. **Held body can launch loose objects: fixed.** `HeldObjectPhysics` has a new `m_MaxHeldSpeed` (default 6 m/s, 0 disables). It clamps the body's linear velocity in `FixedUpdate` while held. XRI's manager runs at execution order -105, so the clamp lands after XRI sets the tracking velocity and before the physics step. Throw velocity is unaffected because XRI computes it from the hand and applies it after release.
4. **Installer runs once: fixed.** `InstallOnSceneLoad` now also subscribes `InstallAll` to `SceneManager.sceneLoaded` (unsubscribes first, so it is safe with Domain Reload disabled). Prefabs instantiated at runtime outside a scene load, and not cloned from an installed object, are still not covered. The code has no such spawn today.
5. **Core behavior untested: tests added.** `HeldObject_IsStoppedByWall_WhenHandPushesThroughIt` drives the hand 3 m through a static wall and asserts the held body stays behind its face. `HeldObject_SpeedIsLimited_WhenHandJumpsAway` checks the clamp. Not run.
6. **Burner snap path untested: test added.** `PanHeldDownOntoStove_AndReleased_SnapsToTheBurnerSurface` holds a pan with `PanSnap`, pushes the hand below a stove slab, asserts the pan stops on the slab, releases it and asserts it ends centered on the `BurnerZone` at the surface height. `Pan.cs` and `PanSnap.cs` are unchanged. Not run, so a hand check of the pan snap is still worth doing.
7. **Other paths: tests added.** `Release_ThrowsObject_WithTheHandVelocity`, `TwoHands_ObjectStaysPhysicsDriven_UntilTheLastHandReleases` and `CloneMadeWhileHeld_StartsWithTheOriginalMovementType`. Not run.

Files changed in this pass: `Assets/Scripts/Common/HeldObjectPhysics.cs`, `Assets/Scripts/Tests/PlayMode/HeldObjectPhysicsTests.cs`, `Assets/Scenes/SampleScene.unity` (two collider size and center values). Nothing was committed, per the briefing.
